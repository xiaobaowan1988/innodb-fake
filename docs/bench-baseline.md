# 并发压测基线（优化前：全局 Mutex + 每步重新下探的游标）

环境：4 核机器，压测客户端(pymysql，每个并发一个进程)与 mysqld 共用 CPU；5 万行；autocommit；
InnoDB 设置 `innodb_flush_log_at_trx_commit=2`，buffer pool 128MB（数据全部命中内存）；
每组 4 秒，单次运行，**同机噪声约 ±10%**，只用于相对比较。复现：`scripts/bench.py --socket /tmp/my.sock`。

## 吞吐 QPS（MyEngine / InnoDB）
| 负载 | c=1 | c=2 | c=4 | c=8 |
|---|---|---|---|---|
| 点查 `id=?` | 4548 / 4701 | 8421 / 8286 | 15885 / 19446 | 14266 / 17806 |
| 范围 100 行 | 1460 / 1706 | 2719 / 2921 | 4591 / 6596 | 4334 / 6424 |
| 二级索引扫描(~500 行+回表) | **887 / 2869** | **942 / 4817** | **784 / 11451** | **757 / 10782** |
| 插入 | 6192 / 1345 | 11954 / 2247 | 15451 / 3345 | 16228 / 4983 |
| 90% 点查 + 10% 更新 | 4724 / 3521 | 8352 / 7355 | 14888 / 14637 | 14240 / 16289 |

## 二级索引扫描 vs 并发（mysqld CPU 占用，100% = 1 核）
| 引擎 | c=1 | c=4 |
|---|---|---|
| MyEngine | 722 qps, CPU 86% | 677 qps, CPU 193% |
| InnoDB   | 2835 qps, CPU 68% | 11348 qps, CPU 254% |

## 结论
- 点查/混合/插入：瓶颈在 SQL 层与网络（每次约 0.18ms），引擎差异被掩盖，MyEngine 与 InnoDB 同量级。
  （插入快于 InnoDB 是因为没有持久化和事务，不是实现更优。）
- 一次要在引擎里做很多步的负载（二级索引扫描、较长范围）明显落后，且**不随并发扩展**：
  MyEngine 加到 4 个并发后吞吐不升反降，p50 从 1.2ms 涨到 5.8ms，而 mysqld CPU 从 86% 涨到 193%
  —— CPU 被消耗但没有换来吞吐，与全局锁争用（多个线程抢同一把 Mutex）一致。
- 单线程下二级索引扫描也慢 4 倍：每行要多次 cgo 调用 + 每步重新从根下探 + 回表再下探一次。
